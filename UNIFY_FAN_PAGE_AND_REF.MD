FULL CURSOR PROMPT — Unify Partner Fan Page Link and Referral Link for Commission Attribution
Important — check existing code first: Before building anything, inspect the existing referral tracking system (the explicit ?ref= URL parameter capture and storage, used for both creator/partner referral links and the Audio Lover referral system). Also inspect the existing fan page / creator profile URL structure (e.g. soundbridge.live/[username]), and how Partner status is currently assigned and stored (the existing partner record structure, referenced elsewhere as including fields like referral code, commission percentage, and role).
The problem this prompt fixes: Currently, a designated Partner only earns 10% commission when a new user signs up via their explicit, separately generated referral link (?ref=partnername). Signups originating from the partner's own fan page link (their regular profile URL, already shared naturally and more frequently than a separate referral link) are not currently attributed to them, creating unnecessary friction for partners who have to remember to use a distinct link instead of the one they'd naturally share.
What to build:
Extend referral attribution logic so that a new user signup is also attributed to a Partner when the immediately preceding page visited was that Partner's fan page (profile URL), even without an explicit ?ref= parameter present.
Implementation approach:
Track the referring page (the last profile or fan page visited) leading up to a signup, using whatever session/referrer tracking mechanism is simplest to implement consistently with existing analytics or session tracking already in place (e.g. capturing the referrer URL or a short-lived session flag when a fan page is visited, checked at the point of signup completion).
If a new user's signup can be attributed to a Partner's fan page visit (and no explicit ?ref= parameter is already present, since explicit referral links should take priority if both signals exist), apply the same referral attribution and commission logic already used for the existing ?ref= parameter flow, crediting that Partner's account.
This attribution should apply only to accounts with Partner status (do not extend this fan-page-based attribution to Item 8's general Audio Lover referral system, that remains explicit-link-only, consistent with Item 23's tiered commission structure).
Scope boundaries:
This prompt only affects how a referral is attributed (fan page visit vs explicit referral link), it does not change commission percentage, payout logic, or eligibility for Partner status itself
Do not apply this fan-page-based attribution logic to non-Partner (regular Audio Lover) referral links, per the tiered commission structure decision already made (Item 23), only designated Partners should benefit from this more permissive attribution method
If explicit ?ref= parameter and fan-page-referrer attribution would both apply to the same signup (e.g. someone visited a partner's fan page, then separately used their referral link), the explicit ?ref= parameter should take priority as the source of truth, not both being counted or causing ambiguity
General rules:
Follow existing code style, referral tracking schema, and commission logic conventions throughout
Ensure this doesn't introduce duplicate commission crediting if a signup could technically match both attribution methods
